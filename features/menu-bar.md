# Menu bar

Adding or removing a queue enrollment fades and gently scales its cards between sections over 0.3 seconds, while surrounding cards and section heights ease into place. Transitions follow confirmed queue changes, including background reconciliation; instruction edits and search do not trigger queue animations. Reduce Motion disables these transitions.

Cards have three appearances: neutral for available chats, amber for queued chats, and red for failed reactivation. Failed cards remain in Queued, retain their instruction and hover removal, and show **Couldn’t resume** with the failure reason. Hover exposes the full reason and recovery guidance; accessibility exposes the same detail. A dispatch without confirmed delivery says **Resume unconfirmed**, and must be inspected before re-queueing. Transient failures retain automatic retry; the red state clears when a subsequent check recovers. Pending approvals, active chats, and quota waits remain amber. Enqueue, editing, and removal errors retain their separate action warning and do not produce the failed reactivation appearance.

Open **Carrie On** (or **Carrie On Menu** for source installations) from Applications. A single status item groups the monochrome C-arrow logo and queued-chat count, followed by a compact next-reset countdown, such as the mark followed by `3 · 2h 14m`. The custom AppKit template mark adapts to light and dark menu bars. The tooltip includes the exact reset time and usage. Clicking anywhere on the item opens the chat picker directly in an anchored popover, with a usage progress bar above the chat cards. The app refreshes passively every minute, on wake, and when opened; the visible popover updates in place. The settings menu offers Launch at Login and Quit Carrie On; Quit stops the app, worker, and local interface. See [startup and quit](app-lifecycle.md). There is no manual refresh action.

Queued and Chats collapse independently and remember their expanded states. Each heading has a separator extending to the right edge, and its entire row toggles the section. A shared search field stays above both sections, including when collapsed, and filters titles in both as you type. Counts reflect matching results. Clearing the query restores both lists without changing queue membership. Queued chats occupy a separate scroll area above the available cards. Both sections sort by last activity, newest first, with unknown times last. Compact cards show titles, projects, and relative last activity (hover for the exact time), highlight on hover, and flip vertically to individual instruction editors when clicked. The placeholder and blank-editor default is **Please continue with your last task.** The instruction editor receives focus when a card flips. Enter submits and returns to the list; Shift–Enter inserts a new line, and Escape returns without submitting. The compact send-arrow **Add to queue** icon sits inside the editor; there are no selection checkboxes, Done control, or batch queue button. Clicking the title or blank body flips back without submitting. Drafts span searches.

Queued cards use amber styling and show an hourglass beside the saved instruction. Hovering over the card front narrows its right edge and reveals a trash button for direct removal. The entire row remains the hover target, including the revealed button. Reduce Motion disables the animation. The instruction editor contains only its save control; removal is available from the card front. Send, save, and trash controls share hover and pressed highlights; destructive controls use red, and disabled controls stay subdued. Edits preserve reset deadlines and require a waiting enrollment whose saved instruction has not changed elsewhere. Removal preserves cancellation history. The usage bar contains its remaining-percentage label and blends continuously between system red at 0%, orange at 50%, and green at 100%. Color and fill changes animate over half a second, unless Reduce Motion is enabled. Its track carries a subtle matching tint, so an exhausted quota still appears red. A compact caption row above it reads **Usage remaining**, with the live reset countdown aligned on the right. Choose a usage bucket when required. Background reads and per-card operations show activity indicators without disabling unrelated controls. Warning icons expose failures on hover, and unconfirmed writes block only the affected card until reconciliation. Newer searches and mutations take precedence over older read responses. The tray has no dashboard navigation or worker-health banner; the settings menu contains the quit action. Paused-queue status and per-card errors remain visible. It shares the local backend service with the browser dashboard but does not require the browser interface to be open. Opening the app from Applications also opens the picker. Login startup uses `--background` to keep it hidden.

The popover inherits the system appearance and accent color, leaving its material to AppKit. AppKit supplies Liquid Glass where supported; compact queue and save controls sit inside the instruction editors. System motion and transparency preferences remain under macOS control.

Instruction edits use the [local action contract](../instruction-api.openapi.json). They require an exact enrollment ID and the previously read instruction; identical retries are safe. The queue lock serializes edits with dispatch. Removal uses the existing cancellation action with the enrollment ID, so a stale card cannot cancel a new enrollment of the same chat.

Run `python3 install_menubar.py` to build, test, sign, install, and start it. The installer accepts `--port` for a nondefault dashboard. The Swift source lives in `menubar/main.swift` and `menubar/ChatPicker.swift`. Background polling reads `/api/menu`, which never includes chat contents or identifiers. The picker uses the existing local chat, status, and enrollment endpoints. See the [guide](../README.md#menu-bar) for semantics, recovery, and removal.

The read-only `/api/queued-chats` endpoint fetches queued metadata independently of search, without loading chat turns. Unavailable metadata retains the enrollment title and reports unknown project and activity. Catalog reads request descending `updated_at` ordering from Codex.

Connection status and refresh activity share a compact footer below the lists, separated by a fine divider. While connected, background usage, chat, metadata, and connection checks replace the status dot with a small spinner while the “Connected to Codex” label stays unchanged. The indicator returns to the connected dot when those reads finish. Offline states retain their explanation during retries; local queue edits keep their per-card feedback. Chat refresh errors appear in the footer with details on hover. The title has no separate refresh or error indicator. A green dot indicates a successful desktop handshake; disconnected states use a muted dot and a concise explanation, with more detail on hover. When Codex is installed but closed, **Open Codex** launches its registered macOS application directly. The button shows **Opening…** while the launch is pending; a failed launch shows a retryable footer message with details on hover. The launcher supports Codex hosted inside ChatGPT and never launches its helper process directly. Usage is hidden while disconnected. macOS app registration and running-app information distinguish **Codex isn’t open**, **Codex isn’t installed**, and **Waiting for Codex**. Both standalone Codex and Codex hosted inside ChatGPT are recognized. A local service failure has its own reconnecting message. Cached cards and saved instructions remain visible; queued instructions can still be edited and removed while Codex is offline. New enrollment waits for a connection. The app retries automatically every minute, on opening, on wake, and when Codex launches or terminates. A restored connection reloads the chat catalog without clearing drafts or queue membership.

The read-only `/api/connection` endpoint performs a desktop handshake with a three-second timeout, without opening chats or running inference. It returns a boolean availability observation, not a guarantee that a later dispatch will succeed. See [the connection API contract](../connection-api.openapi.json). Native self-checks cover missing, closed, unresponsive, and connected states plus offline queue management; HTTP tests cover handshake loss and recovery while preserving queue data.

`python3 -m unittest -v` verifies metadata and partial failure behavior. The native binary's `--self-test` checks decoding, usage selection, future reset selection, unknown data, invalid usage, window labels, picker reconciliation, explicit bucket selection, activity formatting and ordering, shared search across both sections, and per-card action isolation without opening an app or contacting Codex. Installation runs this check before modifying the app bundle. Native click-through tests point the app at an isolated synthetic service, never a production enrollment.
