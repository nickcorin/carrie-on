# Startup and quit

Open the menu-bar picker and its settings menu. **Launch at Login** controls automatic startup of the menu app and backend together. The backend owns the dispatch worker. The preference defaults to enabled for existing installations. Changing it affects future logins, without interrupting the current session. Reinstalling or upgrading preserves the choice.

**Quit Carrie On** asks the backend to shut down through its API, then exits the menu app. Monitoring and dispatch stop; the SQLite queue and instructions remain saved. Opening Carrie On again starts the service regardless of the login preference. Quitting does not change that preference. Work already accepted by Codex continues in Codex; Quit cannot recall it. If service shutdown fails, the app stays open and reports the failure.

Updates and Quit wait up to ten seconds after the shutdown response for the backend to stop running. Its launchd registration stays loaded. A normal shutdown exits successfully and stays stopped; a fatal worker failure exits unsuccessfully so launchd can restart it. If the service does not stop in time, the app reports an error and leaves the installed bundle in place.

Startup settings live in `~/Library/Application Support/Carrie On/Lifecycle/preferences.plist`. The same directory retains `Agents/` definitions for manual launch. When startup is disabled, both app plists are absent from `~/Library/LaunchAgents/`; currently running jobs remain active until Quit. Enabling startup restores those registrations. Installers and the native app share a file lock to prevent conflicting preference changes. Only this profile's service labels are managed.

When manually removing a component, also delete its matching plist from `Lifecycle/Agents/`. Otherwise, a later launch can restore its registration. The CLI's `service uninstall` removes both backend definitions. The bundled `remove-installation` command removes the backend and menu definitions.

`uv run --locked --with-requirements requirements-build.txt python -m unittest tests.test_app_lifecycle tests.test_server tests.test_chat_pagination -v` verifies registration, saved preferences, invalid settings, and removal. It also tests server startup without a Codex executable, graceful HTTP shutdown, exit after worker failure, and the native shutdown request. Native checks use isolated files and a simulated launchd runner. Manual acceptance: disable startup, confirm the app still works, quit and verify the backend and menu stop, then reopen and verify the setting remains disabled and services return. Restore the initial preference after testing. Actual login startup requires a logout/login test.
